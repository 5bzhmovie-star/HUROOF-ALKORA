# حروف الكورة | HUROOF ALKORA — Windows Edition v1.2.0

## فكرة الإصدار
هذا **مشروع التطبيق الحقيقي**: محرك Node.js + قاعدة SQLite + واجهة React محلية مبنية + نافذة WebView2 + شاشة بدء أصلية. يتم إنتاج Windows EXE محمول وحزمة ملفات اللعبة بعد بناء المشروع على Windows. ليس مجرد اختصار للموقع.

## طريقة التشغيل للاعب
بعد إتمام البناء، فكّ ضغط `Huroof-AlKora-Windows-v1.2.0-x64.zip` كاملًا ثم افتح `HuroofAlKora.exe` فقط. لا يحتاج تشغيل كمسؤول، ولا نافذة أوامر. يحتاج توفر Microsoft Edge WebView2 Runtime، وغالبًا مثبت على Windows 11، ويمكن تثبيته رسميًا دون إعادة برمجة اللعبة. لا تفصل مجلد `game` عن ملف EXE.

- **محلي سريع:** يشتغل محرك اللعبة والملفات وقاعدة البيانات على حاسوبك في `127.0.0.1` فقط. ممتاز للمقدم الذي يلعب على الشاشة ذاتها أو للتجربة من نوافذ محلية. أكواد QR على localhost **لا تعمل على جوالات الآخرين**؛ لا نعرضها كغرف عامة صالحة عبر الإنترنت.
- **أونلاين:** يفتح عنوان موقع حروف الكورة الرسمي داخل النافذة المقيّدة. يعمل اتصال الأصدقاء والجرس عبر الخادم المستضاف، إن كان الموقع متاحًا للعامة. بطء الخادم/الإنترنت لن يزول بهذا الوضع لمجرد تشغيل EXE.
- اختصارات: F11 ملء الشاشة، ESC خروج، F5 تحديث، F1 معلومات.

## بناء النسخة الرسمية (مرة واحدة لدى المطوّر فقط)
متطلبات البناء على **Windows 10/11 x64**: Node.js 24، وpnpm 11.19.0، و.NET 8 SDK، والإنترنت لتنزيل حزم البناء. إذا لم يكن pnpm موجودًا: `npm install -g pnpm@11.19.0`.

افتح PowerShell داخل جذر الحزمة:

```powershell
./desktop/scripts/Build-Release.ps1
```

المخرجات:

- `desktop/dist/windows-x64/HuroofAlKora.exe` (برنامج Windows أصلي؛ مستخدم النهاية لا يحتاج .NET SDK أو Node.js مثبتًا).
- `desktop/dist/windows-x64/game/` (محرك Node.js Windows محمول، ملفات واجهة اللعب والأسئلة، وملفات الخادم).
- `desktop/dist/Huroof-AlKora-Windows-v1.2.0-x64.zip` (الإصدار المحمول الذي توزعه كاملًا).
- `desktop/dist/Huroof-AlKora-Windows-v1.2.0-x64.zip.sha256.txt` (بصمة الملف للتحقق).

**تقدر تبنيه دون تثبيت أدوات البناء على جهازك** باستخدام `.github/workflows/windows-build.yml` في مستودع GitHub لك، وتشغيل workflow من Actions؛ تحصل على ZIP مكتمل في Artifacts. لا ترفع أسرارًا أو بيانات مستخدمين إلى المستودع.

## التوزيع والمتجر

- التشغيل المحمول: فكّ ZIP كاملًا؛ لا يتطلب مسؤول نظام أو مثبتًا.
- Microsoft Store: احجز هوية التطبيق في Microsoft Partner Center؛ استخدم نفس قيم `IdentityName`, `Publisher`, `PublisherDisplayName` بالضبط لإنشاء MSIX غير موقعة:

```powershell
./desktop/scripts/Build-MSIX.ps1 -IdentityName 'القيمة_من_Partner_Center' -Publisher 'CN=... من Partner Center' -PublisherDisplayName 'Yazn Abdulaziz'
```

- يجب اختبار الحزمة على Windows، وفحص Microsoft Store Certification Kit ثم رفعها للحساب لعمليات المراجعة والتوقيع. ملف MSIX المحلي **ليس جاهزًا للتثبيت العام دون توقيع**. كذلك تحتاج صفحة خصوصية ومحتوى المتجر وصورًا وشعارًا وتوافقًا مع السياسات.

## نموذج الحماية — بدون مبالغة

1. ملف EXE يستخدم `asInvoker` (صلاحيات المستخدم العادي فقط)، لا يطلب UAC للتشغيل. تطبيق سطح مكتب عادي وليس AppContainer معزولًا بالكامل.
2. لا توجد واجهة أوامر للنظام من JavaScript، ولا `nodeIntegration`، ولا كائنات مضيف معروضة للصفحة. الرسائل المحلّية المقيدة تتحكم فقط في العرض والتحديث.
3. يمنع الموقع الداخلي طلب أذونات الكاميرا/المايكروفون/الموقع وإطلاق التنزيلات مباشرة، ويعطّل DevTools والقوائم غير الضرورية. منع DevTools **ليس نظام منع غش**.
4. يمنع الانتقال داخل WebView2 إلى مواقع غير معتمدة، ويفتح روابط HTTPS الخارجية في المتصفح الافتراضي.
5. خادم اللعبة المحلي مربوط في loopback فقط؛ لا يفتح منفذًا للعالم. جلسات وضوابط CSRF وتحقق صلاحيات المضيف/اللاعب على الخادم. بداية الخادم تتحقق برمز عشوائي خاص بكل تشغيل.
6. محرك Node يعمل بنموذج أذونات لتقييد القراءة إلى اللعبة والبيانات المحلية والكتابة لبيانات المستخدم، دون منح صلاحية تشغيل عمليات فرعية. **نموذج أذونات Node ليس عزلًا مضمونًا أمام تعليمات خبيثة، ولا يمنع كل وصول ممكن إلى الملفات، خصوصًا عبر SQLite.**
7. البيانات المحلية في `%LOCALAPPDATA%/HuroofAlKora/data`. حسابات وإحصاءات المباريات المحلية قابلة للتعديل بيد مالك الجهاز؛ لذلك لا تُقبل كإحصاءات عامة موثوقة. نتائج المنافسة العامة وأذونات الإدارة يجب التحقق منها على خادم أونلاين تديره أنت.
8. لا يوجد في حزمة EXE مفتاح خاص للإدارة أو خادم عام أو تحديث تلقائي غير موثوق. التوقيع الرقمي والتحديثات الموثوقة فائدة أساسية للنشر الرسمي في Microsoft Store.

لا توجد حماية تجعل اختراق التطبيق "بلا أثر" تمامًا. البرمجيات التي تعمل بصلاحية المستخدم قد تعرّض ملفاته للخطر إذا كانت فيها ثغرة تنفيذ تعليمات؛ لذلك نلتزم بتحديثات الأمان، أقل الصلاحيات، تدقيق الحزم، والتحقق الخادمي.

## قياس السرعة
المشروع مبني على v15 المحسنة: SSE لخادم الغرف المحلي، تحديث حالة الغرفة فقط عند تغيرها، عداد محلي مستقل، `React.memo` للشبكة، وذاكرة للتجميع المضغوط للموارد. الاستفادة الفعلية تعتمد على التحميل والأجهزة وطبيعة الغرفة. اختبارات Node للوظائف والأمان **لا تعد اختبارًا لأداء اللعبة على Windows**.

## حدود ما تم اختباره هنا
جرى اختبار الخادم واستخدام Node Permission Mode وhandshake على Linux، وكذلك تدقيق ملفات المشاريع. لم يجرِ `dotnet publish` أو اختبار UI أو تغليف MSIX فعلي هنا لعدم وجود Windows SDK/.NET/Node 24/dependencies في بيئة التنفيذ. لذلك لا تعتبر هذا الأرشيف نفسه EXE مكتملاً؛ هو **مصدر للإصدار الكامل قابل للبناء على Windows**.
