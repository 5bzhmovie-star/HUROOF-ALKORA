# استيراد بيانات المكتبة باستخدام PHP وMySQL

هذا المسار يستورد بيانات المكتبة الحالية، ولا يحول لعبة Node/React الحالية إلى تطبيق PHP، ولا يشهد باكتمال المحتوى أو الصور.

## المتطلبات

PHP 8.0 أو أحدث مع PDO وpdo_mysql، وMySQL 8.0.16 أو أحدث أو MariaDB 10.11. الاختبار الفعلي تم باستخدام PHP 8.3 وMariaDB 10.11.14. لا يتطلب تشغيل المستورد Node.js.

يُحفظ مجلد الاستيراد والتصدير خارج مجلد الملفات العامة. المستورد يعمل من سطر الأوامر فقط ويرفض التشغيل عبر HTTP. قاعدة البيانات تختار من إعدادات الاستضافة؛ لا يكتب المستورد بيانات دخول داخل المشروع.

## ملفات الإدخال والتشغيل

لقطة البيانات الموجودة حاليًا في `data/catalog.sqlite` تضم بيانات كأس العالم المستوردة فقط: 1345 كيانًا و2496 سجل معلومة، مع العلاقات والأعلام. بيانات الأندية المجموعة الأخرى محفوظة كملفات مرشحين منفصلة، ولم تُدمج بعد في هذه اللقطة. لا تستبدل بها قاعدة اللعبة القائمة.

تصدير هذه اللقطة الجاهز موجود في `data/mysql-snapshot`. شغّل `php import/import.php data/mysql-snapshot` بعد ضبط متغيرات البيئة التالية. ولصنع تصدير آخر، صدّر قاعدة SQLite عبر `scripts/export_snapshot.py` إلى مجلد جديد. يتضمن `index.json` فهرس الأجزاء وأعداد الصفوف وبصماتها. ينقل التصدير الحقول والتواريخ وحالات المراجعة كما هي؛ لا يحول حالة pending إلى reviewed.

اضبط متغيرات البيئة `HA_IMPORT_DSN` بصيغة `mysql:host=HOST;dbname=DATABASE;charset=utf8mb4`، و`HA_IMPORT_USER`، و`HA_IMPORT_PASSWORD` من إعدادات الاستضافة الخاصة. لا تُضع كلمة المرور في رابط أو ملف عام أو سجل طرفية مشترك.

شغّل `php import/import.php PATH_TO_EXPORT_DIRECTORY`. يُنشئ المستورد جداول ببادئة `huroof_library_` ولا يعدّل جداول الحسابات أو الغرف أو الأسئلة في اللعبة. جداول العلاقات تحمل مفاتيح أجنبية وفهارس. الجداول تُنشأ قبل معاملة البيانات لأن MySQL ينفذ DDL خارج معاملات إدخال الصفوف.

## التحقق والحماية

قبل الاتصال بقاعدة البيانات تُفحص جميع أجزاء JSON ومساراتها وبصماتها وأعدادها وأعمدتها وقيمها. إدخال الصفوف وتسجيل إيصال الاستيراد ضمن معاملة واحدة؛ إذا فشل أي مفتاح أجنبي تتراجع جميع الصفوف، وقد تبقى الجداول الفارغة التي أنشأها المخطط.

إعادة استيراد اللقطة نفسها لا تضيف سجلات. إذا وُجدت بيانات أخرى أو لقطة مختلفة يرفض المستورد الاستبدال، وتحتاج التحديثات المستقبلية إلى ترحيل مدروس. القفل يمنع عمليتي استيراد متزامنتين. نجاح الاستيراد يعيد JSON بأعداد الصفوف الفعلية و`releaseReady=false`.

## تركيب ملفات الصور المحلية

تتضمن `assets/bundles` الملفات الأصلية ضمن حزم TAR محلية وفهرسًا ببصمات SHA-256 ومسارات الاستخراج. لا تُجلب الصور من الإنترنت وقت التركيب. من داخل `football-library` شغّل:

```sh
php import/media.php
php import/media.php --verify
```

يتحقق المستخرج من جميع الحزم والمحتويات قبل الكتابة، ثم يضع الصور في مسارات `assets/pending_media` المحددة في `data/media_files.index.json`. يعيد التشغيل دون تكرار الملفات الصحيحة، ويرفض استبدال ملف مختلف. لا يحتاج ZipArchive أو Phar أو Node.js، ولا يعمل عبر HTTP. احتفظ بالحزم خارج المسار العام. تُحفظ الصور الأصلية دون إعادة ضغط أو تغيير الملامح.

الفهرس الحالي يضم 922 ملفًا فعليًا، مع روابط أدلة المصدر وحالة حقوق الاستخدام المعلقة. وجود الملف وفحص بصمته لا يثبت هوية الشخص أو صحة القميص أو حقوق إعادة التوزيع؛ لا تُعتمد الصور للأسئلة قبل إتمام تلك المراجعة. ملفات الأعلام الموجودة منفصلة عن هذا العدد.

مستورد MySQL لا يتيح نقاط HTTP لعرض الصور. واجهة العرض PHP وربط جميع بيانات المرشحين بالكيانات الموحدة تبقى ضمن العمل المطلوب.

## اختبارات التطوير

`tests/test_php_import.py` يستخدم قاعدة اختبار منفصلة عبر `HA_IMPORT_DSN` وقاعدة فارغة أخرى عبر `HA_TEST_ROLLBACK_DSN`. الاختبارات تنفذ الاستيراد الحقيقي وإعادته، ورفض ملف معدل، وحفظ الحالات المعلقة، وفشل علاقة وإثبات خلو جميع الجداول بعدها. لا تُشغّل هذه الاختبارات على قاعدة الإنتاج. عند عدم توفير قاعدة اختبار تُعلن الاختبارات أنها متجاوزة ولا تُحسب ناجحة.

## ملفات الإحصاءات الموسعة

`data/statistics/compressed_candidates.index.json` يفهرس نسختين JSON مضغوطتين بصيغة gzip، مع بصمتي الملف المضغوط ومحتواه الأصلي. الضغط يحفظ جميع البايتات ولا يغير القيم. تتضمن إحصاءات المصدر حقولًا وأسماء بديلة وليست كل قيمة مقياسًا مستقلًا. تبقى التعارضات والقيم غير الصالحة معزولة داخل الأدلة؛ لا تُنشر تلقائيًا كأسئلة أو كإحصاءات معتمدة.

## ربط أصول لقطة SQLite

ملف `data/catalog_media.index.json` يربط معرفات `visual_assets` وأسماء ملفاتها التشغيلية بملفات الأعلام PNG الموجودة فعليًا في `assets/national_teams` وبصماتها. تستخدم واجهة PHP المستقبلية هذا الربط أو تنقل الملفات إلى مجلد الوسائط التشغيلي المحدد لها؛ لا تفترض أن الاسم العشوائي في جدول الوسائط يطابق اسم العلم على القرص. في اللعبة الحالية، يقوم `website/scripts/import-fifa-snapshot.mjs` بتثبيت الأعلام داخل مجلد DATA_DIR مع تسجيل أسمائها الصحيحة. لا تُستبدل قاعدة اللعبة بملف catalog.sqlite.
