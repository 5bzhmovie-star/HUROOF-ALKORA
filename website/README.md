# حروف الكورة

منصة ألعاب كروية عربية جماعية: لعبة حروف الكورة الأساسية، وقسم **Mini Games** مستقل يضم ٣١ لعبة بصرية. تحتوي الحزمة على الواجهة المبنية، وكود المصدر، وخادم اللعبة، وبنك **٦٧٣٣ سؤالًا** عن البطولات نفسها، ومحتوى Mini Games موثق، واختبارات، وأدوات إدارة ونسخ احتياطي.

## التشغيل السريع

تحتاج **Node.js 24 أو أحدث**. النسخة المبنية مرفقة؛ لا تحتاج تثبيت حزم لتشغيلها.

1. فك ضغط الحزمة في مجلد قابل للكتابة.
2. على Windows افتح `START-WINDOWS.bat`، أو نفّذ داخل المجلد:

```sh
node --env-file-if-exists=.env server/index.mjs
```

3. افتح `http://localhost:3000`، واضغط «إنشاء غرفة لعب».
4. اختر الفرق والبطولات والمقدم والحجم، وأدخل اسمك مع التحقق المرئي.
5. من لوحة المقدم افتح شاشة العرض وشارك رابط/QR الجرس.

ينشئ الخادم قاعدة SQLite تلقائيًا عند أول تشغيل ويحمّل الأسئلة إليها. تعديل ملف الأسئلة لاحقًا لا يستبدل قاعدة موجودة؛ استخدم الاستيراد من لوحة الإدارة.

**الأجهزة الأخرى:** localhost يعمل على جهاز الخادم فقط. للعب على شبكة محلية، انسخ `.env.example` إلى `.env` واجعل `APP_ORIGIN=http://192.168.1.20:3000` بحسب عنوان جهازك، ثم شغّل بالأمر أعلاه وافتح هذا العنوان من كل الأجهزة. اسمح للمنفذ في الشبكة الخاصة. استعمل HTTPS عند الاستضافة العامة؛ لا تستخدم HTTP لإدارة موقع عام.

## إنشاء مدير الموقع

لا توجد كلمة مرور افتراضية أو حساب إدارة جاهز. نفّذ في طرفية تفاعلية:

```sh
node --env-file-if-exists=.env scripts/create-admin.mjs
```

اختر اسم المستخدم وكلمة مرور من ١٤ حرفًا أو أكثر. أضف سر TOTP الذي تعرضه الأداة إلى تطبيق المصادقة، ثم أدخل رمزه لتأكيد التفعيل. افتح `/admin` وسجّل الدخول بكلمة المرور ورمز المصادقة. احفظ نسخة استرداد آمنة من سر المصادقة؛ لا ترسله للاعبين. يمكن للمالك دعوة مدير أو مشرف أسئلة من اللوحة.

## ما يعمل في النسخة

- إنشاء غرف نشطة وشبكات سداسية 4×4 إلى 7×7، وأسماء وألوان فرق قابلة للتحديد. تُحذف الغرف العادية وغرف Mini Games بعد ١٠ دقائق من الخمول.
- مقدم بشري أو إدارة ذاتية من جهاز مشترك، وشاشة عرض منفصلة لا تتلقى الإجابة المخفية. أثناء السؤال والجرس تفحص الشاشات الحالة كل ١٥٠ ملّي ثانية، وتبطئ إلى ٥٠٠ ملّي ثانية فقط عند انتظار اختيار حرف.
- جرس لحظي عبر SSE وطلبات HTTP، يحسم الخادم أول ضغطة بمعاملة واحدة؛ عداد ٥–٢٠ ثانية وإعادة فتح اختيارية.
- كشف الإجابة واعتماد الفريق، تصحيح الخلايا، تراجع، تغيير سؤال، اكتشاف المسار والفوز، وإعادة المباراة.
- دخول اللاعبين بأسماء مستعارة، اختيار فريق، حذف لاعب، واستعادة الهوية عبر كوكي آمن.
- حساب خفيف بإحصاءات المباريات والفوز، وإدارة للأسئلة والبطولات والغرف والمستخدمين والإعدادات والأدوار والسجلات.
- ثيم صباحي ومسائي، أصوات اختيارية، تصميم متجاوب، QR محلي، وPWA مع شاشة انقطاع اتصال.
- زر دعم اختياري يظهر بعد وضع رابط دفع خارجي آمن في إعدادات الإدارة؛ الموقع لا يجمع معلومات البطاقة.
- ١١ بطولة وبنك أسئلة في قاعدة البيانات؛ يمكن إنشاء بطولات واستيراد الأسئلة من الإدارة.
- ٣١ Mini Game قابلة للعب بغرف حقيقية، وفريقين، وكود مخفي، ورابط جرس وQR وشاشة عرض ونتيجة وجولات فاصلة عند التعادل.
- صور لاعبين وشعارات وأعلام وملاعب ببدائل نصية واضحة ومصدر يظهر بعد كشف الحل. لعبة وصف المباراة تستخدم نطقًا عربيًا أصليًا من الجهاز مع زر كتم وحد أقصى تشغيلان للجولة.
- لوحة الإدارة تعرض محتوى Mini Games وتسمح بتعديله وإخفائه وحذفه، كما تعرض غرفه المفتوحة وتسمح بإغلاقها.

## نسخة ChatGPT Sites

يُبنى الموقع أيضًا إلى Cloudflare Workers مع قاعدة D1 مشتركة بدلاً من قاعدة SQLite المحلية. هذه النسخة تحتفظ بالواجهة والغرف والأسئلة والجرس وMini Games وإدارة المحتوى والبطولات والإعدادات. التحديثات النشطة تتم كل ١٥٠ ملّي ثانية وتتباطأ إلى ٥٠٠ ملّي ثانية عند الانتظار. هوية مالك لوحة الإدارة مثبتة مسبقًا في قاعدة الموقع ولا يستطيع أول زائر المطالبة بها. أضف من **الإدارة ← الإعدادات** رابط دعم يبدأ بـ `https://`؛ يظهر الزر عند الحفظ، ومسح الرابط يخفيه.

للنشر عبر Sites شغّل `npm run build`، أما حزمة الاستضافة الذاتية فابنِ واجهتها بـ`npm run build:selfhost`. لا ترفع مجلد `data` إلى المستودع أو إلى نسخة Sites.

## النشر الذاتي

هذه حزمة استضافة ذاتية على **خادم Node واحد بقرص دائم**. ليست ملفات HTML فقط، ولا يعمل خادم Node نفسه على استضافة صفحات ثابتة؛ مسار البناء الخاص بـSites يعمل على Cloudflare Workers. قاعدة البيانات والاتصالات اللحظية تعمل على الخادم؛ لا تشغّل عدة نسخ/عمال من التطبيق على القاعدة نفسها. التوسع الأفقي يحتاج قاعدة مشتركة ووسيط بث.

1. ارفع الحزمة إلى خادم Node 24 أو خادم Docker.
2. انسخ `.env.example` إلى `.env` واضبط `APP_ORIGIN=https://game.example.com` على نطاقك الفعلي و`NODE_ENV=production`.
3. جهّز شهادة TLS ووكيل Nginx باستخدام `deploy/nginx.conf.example` مع استبدال النطاق ومسارات الشهادة.
4. شغّل `docker compose up -d --build`، أو شغّل Node تحت مدير عمليات خادمك. ملف Docker يستخدم الواجهة المبنية المرفقة.
5. لإنشاء المالك داخل Docker: `docker compose exec app node scripts/create-admin.mjs`.
6. اضبط `TRUSTED_PROXY_IP` على **عنوان الوكيل كما يراه Node فقط**؛ اتركه فارغًا إذا لم يكن لديك وكيل موثوق. لا تقبل عناوين X-Forwarded-For من الإنترنت مباشرة.
7. يمكن تفعيل Turnstile بمفتاحي `TURNSTILE_SITE_KEY` و`TURNSTILE_SECRET_KEY`. بدونهما يعمل تحقق الصورة المحلي مع تحديد المعدل؛ الصورة ليست بديلًا مكافئًا لخدمة مكافحة الروبوتات المتقدمة.
8. فعّل WAF لدى مزود نطاقك/استضافتك وطبّق حدود المعدل المناسبة. هذه إعدادات بنية تحتية وليست مفعّلة على حساب خارجي تلقائيًا.

الحزمة لا تتضمن أسرارًا أو قاعدة مستخدمين. مجلد `data` يُنشأ عند التشغيل ويجب أن يبقى خاصًا، خارج جذر الملفات العامة. لا تحذف مفتاح التشفير الموجود فيه؛ تحتاجه لفك أسرار المصادقة بعد الاستعادة.

## النسخ الاحتياطي والاستعادة

```sh
node --env-file-if-exists=.env scripts/backup.mjs
```

ينتج مجلدًا مؤرخًا يحوي لقطة SQLite متسقة ومفتاح تشفير وبيانات النسخة. يُسمح بالنسخ أثناء تشغيل الخادم. مثال جدولة يومية في `deploy/backup.cron.example`؛ فعّلها على خادمك وانسخ الناتج إلى تخزين خاص منفصل ومشفّر. راقب المساحة واحتفظ بالمدة التي تناسبك.

للاستعادة: أوقف الخادم، وحدد مجلد وجهة جديدًا وفارغًا:

```sh
node scripts/restore.mjs /absolute/path/to/backup /absolute/path/to/restored --server-stopped
```

تتحقق الأداة من سلامة القاعدة والعلاقات، وتلغي الجلسات القديمة. اضبط `DATA_DIR` على المجلد المستعاد وشغّل الخادم. يلزم تسجيل الدخول من جديد. لا تستعد فوق قاعدة تعمل. في Docker حافظ على حجم البيانات الدائم وانقل النسخ خارجه؛ لا تعتمد على بقاء الحاوية.

## بنك الأسئلة

راجع `docs/QUESTIONS.md` للتوزيع والمصادر وحدود المحتوى. يحتوي كل سؤال على بطولة وحرف ونص وإجابة وصعوبة وحالة ومصدر. تُوحّد الهمزات وتُتجاهل «الـ» في مطلع الإجابة. الحروف غير المغطاة لا تُولّد في اللوحة. المستويات أو الاختيارات القليلة قد لا تكفي للحجم المطلوب، وعندها يطلب الموقع توسيع الاختيار. لا تُكرر الأسئلة المستخدمة داخل المباراة؛ تغيير السؤال متاح ما دام له بديل. إعادة المباراة تبدأ رصيد الأسئلة من جديد.

للاستيراد، استخدم JSON من زر التصدير كقالب؛ الحد ٢٠٠٠ سؤال في الدفعة وحجم الطلب محدود. الحقول: `tournament_id, letter, text, answer, difficulty, status, source, note`. الصعوبات `easy|medium|hard` والحالات `published|hidden`. لا تضع إجابات ضمن ملفات الواجهة.

## تعديل الكود والتحقق

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm build
node --test tests/*.test.mjs
```

يمكن أيضًا تشغيل مدير pnpm المثبت عندك مباشرة. الواجهة React/TypeScript وVite، وCSS عربي واتجاه RTL، ومكونات shadcn. الخادم Node HTTP + SQLite؛ لا يحتاج خدمات ذكاء اصطناعي أو مفاتيح API للعب الأساسي. ملفات `app` هي مسار النشر الخاص بـSites؛ أما خادم Node الذاتي فيستخدم `server/index.mjs` وواجهة `dist/client`.

- `client/`: صفحات ومكونات اللعبة.
- `server/`: الصلاحيات والجلسات والجرس وقواعد اللعب وSQL.
- `seed/`: الأسئلة ومصادر توليد البنك.
- `public/`: خطوط وأيقونات وPWA وصورة المشاركة.
- `dist/client/`: واجهة جاهزة للتشغيل.
- `tests/`: اختبارات منطق اللعبة وواجهات HTTP والأمن والاستعادة.
- `docs/VALIDATION.md`: نتيجة الفحص وحدود الجاهزية.

**حالة التسليم:** الموقع منشور على [رابط حروف الكورة](https://huroof-alkora.yaznabdulaziz1.chatgpt.site). البناء وفحص TypeScript وحزمة الاختبارات الآلية موثقة في `docs/VALIDATION.md`. لم يُنفّذ فحص Kali مستقل أو اختبار أجهزة فعلية أو قياس حمل إنتاجي؛ تفاصيل السيناريو في تقرير التحقق.
