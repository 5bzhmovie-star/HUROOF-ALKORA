# تقرير التحقق — ١٨ سبتمبر ٢٠٢٦

## النتيجة المنفذة

- بناء واجهة الإنتاج عبر Vite: ناجح.
- TypeScript دون إخراج ملفات: ناجح.
- `node --test tests/*.test.mjs`: **٣١ ناجحًا، صفر فشل**.
- فحص ١٨ رابط مصدر فريدًا: **١٨ ناجحًا، صفر روابط معطلة**.
- بيئة الاختبار Node.js 24.19.0، Linux، SQLite محلية في مجلد اختبار معزول.

تختبر حزمة التكامل خادم HTTP فعليًا بعدة جلسات كوكي مستقلة، وليس محاكاة لردود API. اختبرت إنشاء غرفة ودخول فريقين، عرض الإجابة بحسب الدور، SSE وتحديث حالته، وصول ضغطتي جرس متزامنتين وقبول واحدة، رفض إعادة الضغط، انتهاء العداد، كشف الإجابة وامتلاك الخلايا، اتصال مسار الفوز، الإحصاءات، التراجع عن الفوز وإعادته، إعادة المباراة، إعادة إنشاء خادم HTTP مع الحالة المحفوظة، الوضع الآلي، وطرد لاعب.

تختبر حزمة Mini Games وجود ٣١ لعبة وجولتين موثقتين على الأقل لكل لعبة، وبنية المرئيات ومصادر الوسائط وبدائلها النصية. ويغطي اختبار الغرف إنشاء الغرفة، الدخول لفريق، إخفاء الحل قبل الكشف، حسم أول جرس من الخادم، كشف الحل واحتساب النقطة، حد تشغيل الوصف الصوتي مرتين، وحذف الغرف العادية والمصغرة بعد ١٠ دقائق من الخمول.

اختبار الاستعادة أنشأ نسخة حقيقية أثناء فتح SQLite واستعادها في مجلد منفصل، وفحص `integrity_check` والعلاقات، وبقاء نتائج المباريات، وإلغاء الجلسات القديمة.

اختبارات المنطق تشمل كل التلوينات الثنائية الـ٥١٢ للوحة 3×3 والتحقق من فائز واحد، وتوافق مجاورات الخلايا السداسية، وإمكان تشغيل كل بطولة بمفردها لجميع الأحجام إلى 7×7، وعدم تكرار النصوص والمعرفات ومطابقة الحروف. كما تتحقق من وجود أكثر من ٥٠٠٠ سؤال، ووجود بنك مستقل وكافٍ لكل بطولة، ومنع أسئلة القوانين والمصطلحات العامة من الظهور داخل أقسام البطولات.

فُحصت روابط المصادر الفريدة بأداة مستقلة ونجحت الروابط الـ١٨ كلها باستجابة HTTP ناجحة يوم ١٥ سبتمبر ٢٠٢٦. يعاد الفحص بالأمر `npm run questions:check-links` لأن صلاحية الروابط الخارجية قد تتغير مستقبلًا.

## ضوابط منفذة واختبارات موجهة

| المجال | التنفيذ والتحقق |
|---|---|
| التحكم بالوصول | تحقق خادمي من مالك الغرفة وعضوية اللاعب وأدوار الإدارة. رُفض انتحال الدور والوصول العرضي لغرفة أخرى. |
| كشف الإجابات | إسقاط مخصص للعرض والجرس؛ اختبار JSON وأحداث SSE قبل الكشف وبعده، بما يشمل فتح المالك لشاشة العرض. |
| الجلسات | معرف عشوائي، تخزين البصمة فقط، تدوير بعد إثبات الهوية، HttpOnly وSameSite=Strict، وSecure وHSTS عند أصل HTTPS. |
| CSRF/CORS | تحقق Origin وCSRF على الكتابة، وعدم منح CORS لمواقع أخرى؛ اختبارات رفض فعلية. |
| إدارة | scrypt لكلمات المرور، TOTP إلزامي ومنع إعادة استعمال الرمز، تشفير أسراره، وثلاثة أدوار. لا حساب افتراضي. |
| SQL/XSS | استعلامات بمعاملات وReact للنصوص، CSP، رفض رموز تحكم وأسماء غير مناسبة تقنيًا. اختبار إدخال SQL في البحث؛ لا يدعي فحص XSS متصفحًا شاملًا. |
| الجرس | معاملة خادمية وتوليد مفتاح لكل دور وسؤال، حدود معدل، ورفض النسخ القديمة من أحداث التحكم. |
| سرعة اللعب | فُصل بنك الأسئلة عن مسار تشغيل API، وصار اختيار السؤال يعيد سجلًا واحدًا من قاعدة البيانات بدل نقل القائمة كاملة. تُنفّذ قراءة اللاعب والجلسة باستعلام واحد، وتُنفّذ كتابة الحالة والحدث دفعة واحدة، وتُقرأ بيانات المقدم بالتوازي. المتابعة متكيّفة كل ١٥٠ ملّي ثانية أثناء السؤال والجرس و٥٠٠ ملّي ثانية عند الانتظار لتجنب ازدحام الطلبات مع بقاء الاستجابة شبه فورية. |
| Mini Games | غرف محفوظة في الخادم مع كود ورابط جرس وشاشة عرض، إسقاط يمنع الحل قبل الكشف، جرس يحسمه الخادم، مصادر بعد الكشف، وصوت عربي من الجهاز بحد تشغيلين. |
| الملفات | تقديم ملفات الواجهة المبنية فقط؛ اختبارات أن قاعدة البيانات والمصدر والإعدادات لا تُخدم. |
| النسخ | نسخة قاعدة ومفتاح؛ تحقق استعادة وإلغاء جلسات. |
| الخصوصية | اسم مستعار وهوية عشوائية؛ لا بريد ولا هاتف للاعب. بصمات مؤقتة لتحديد المعدل. |

هذا ربط مبدئي بمخاطر OWASP Access Control وAuthentication وInjection وSecurity Misconfiguration وAPI Resource Consumption. لا يمثل تدقيقًا مستقلاً لجميع بنود OWASP أو شهادة أمنية.

## خطوات لم تنفذ داخل هذه البيئة

- أُجريت معاينة بصرية للصفحة الرئيسية وكتالوج الألعاب وإعداد الغرفة في متصفح سطح مكتب، وتأكد ظهور الألعاب الـ٣١ دون تمرير أفقي. لم تُجرَ معاينة على أجهزة فعلية أو فحص شامل بقارئ شاشة.
- لم يُنفّذ Kali Linux أو ZAP أو فحص اختراق مستقل، ولا مسح محدث لثغرات جميع التبعيات.
- لم تُختبر شهادة TLS وNginx وDocker وWAF على نطاق مستضاف فعلي. وجود ملفات إعداد لا يعني نشرها أو تفعيلها.
- لم يُنفّذ اختبار حمل إنتاجي أو مقارنة تأخير شبكات اللاعبين. أولوية الجرس هي ترتيب الوصول للخادم، لا الساعة المحلية لكل هاتف.
- WebMCP ميزة اختيارية لقراءة العرض العام فقط؛ لم يتوفر سياق متصفح داعم للتحقق من التسجيل والتنفيذ.
- لم تُراجع جميع الأسئلة يدويًا بواسطة محرر مستقل.

لذلك لا تُعد بوابة الإطلاق العام في وثيقة المتطلبات مجتازة بالكامل. الحزمة قابلة للتشغيل والرفع، وتحتاج تحقق النشر والمتصفحات والفحص الأمني قبل إعلان V1 عامة.

## قبول نهائي على بيئة تملكها

1. افتح الموقع على لابتوب مقدم، وشاشة عرض، وهاتفين على شبكتين إن أمكن؛ اختبر مقاسات ٣٦٠ و٧٦٨ و١٤٤٠ وشاشة تلفزيون، والثيمين والتكبير والتنقل بالكيبورد.
2. أنشئ غرفة بكل إعداداتها، وامسح QR بهاتف، وادخل باسم وفريق من الهاتفين. تحقق أن الشاشة لا تعرض أدوات المقدم أو الإجابات المخفية.
3. اختر حرفًا وافتح الجرس واضغط من الهاتفين؛ يجب تثبيت اسم واحد وإغلاق الجرس عند الجميع. تحقق من الصوت والوقت وإعادة الفتح.
4. اكشف الإجابة واحتسبها؛ افصل هاتفًا ثم أعد الاتصال وحدّث الشاشة. يجب استعادة الحالة دون إعادة حساب نقطة.
5. أكمل مسارًا وتحقق من الفوز والإحصاءات؛ تراجع وأعد احتساب الخلية وأعد المباراة. جرّب أيضًا الوضع الآلي.
6. أعد تشغيل عملية Node، واختبر بقاء الغرفة. اختبر نسخة احتياطية واستعادة على مجلد منفصل قبل استعمالها في تعافٍ حقيقي.
7. على نطاق تجريبي مصرح فقط، افحص المصادقة والصلاحيات وCSRF وXSS وAPI وتسريب الملفات والجلسات. استخدم ZAP/Kali والفحص اليدوي، وأصلح النتائج العالية وأعد اختبارها قبل فتح الموقع للعامة.
8. جرّب حمل عدد المستخدمين المستهدف، واضبط حدود المعدل والموارد والنسخ والمراقبة بناء على قياسك.
